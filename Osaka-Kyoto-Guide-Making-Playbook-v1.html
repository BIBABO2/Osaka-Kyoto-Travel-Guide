大阪・京都旅游攻略 制作指南（v1）

版本：v1 ｜ 整理日期：2026-09-09 ｜ 类型：攻略制作方法 / 工具评估 / 更新规程（面向后续修订者与 AI 助手）
配套攻略：〔Osaka-Kyoto-NationalDay-Travel-Guide-v1.md〕（面向出行者的“完全旅游注意事项攻略”）

本指南回答三类问题：这份攻略是按什么要求做的（任务要求）、用什么工具和方法做的（工具评估与验证规则）、以后如何更新（版本与流程）。这类内容不再放进旅游攻略正文。

1. 文档定位与版本管理

  • 两个文档各自独立、均带版本号：
  • 攻略 v1：Osaka-Kyoto-NationalDay-Travel-Guide-v1.md
  • 制作指南 v1：Osaka-Kyoto-Guide-Making-Playbook-v1.md
  • 版本规则：正文内容有实质变化（新增章节、政策/票价/时刻更新、来源增删）时，两个文档同步升版本号（v1 → v2），并在各自“更新记录”登记日期与改动摘要。
  • HTML 检索版由 Markdown 生成（见第 7 节），文件名随版本同步，例如 …-v1.html。

2. 任务原始要求（v1 依据）

用户最初提出的核心要求（v1 按此执行）：

  1. 按“出发前（准备阶段）/ 入境前（深圳至入境）/ 抵达后（入境后至京都酒店）/ 旅游阶段 / 离境”五段整理注意事项，覆盖衣食住行、购物注意事项、风土民俗、游玩建议。
  2. 先在 GitHub 上寻找相关的高质量“旅游攻略制作 Skills”，验证可行性与适配性；同时全网检索攻略制作方法，找出“最准确、最靠谱”的信息获取方式。
  3. 重要信息需要多重、多渠道验证；不确定信息必须标注清楚。
  4. 可参考小红书（2025 年至今）真实内容，但也存在不准确信息；重要信息需确认是否最新；每条信息附来源以便验证真伪。
  5. 判断是否需要额外 MCP/插件工具；优先“免费、无需注册第三方收费平台、可通过公开互联网信息完成、可使用现有浏览器/网页搜索/网页读取能力”的方案；现有能力够用就不安装。
  6. 输出文档需方便检索（窗口/文件中可查看目录）。

3. 工具调研结论（v1 执行记录）

3.1 GitHub Skills 检索与评估

  • 检索到的主要候选：
  • skywain/trip-planner-skill（MIT）：一句话生成逐小时行程并渲染主题 HTML/PDF；用工具核对营业时间与票价；依赖 Python 包，可选图片生成需要 API key（有免费 stock 兜底）。https://raw.githubusercontent.com/skywain/trip-planner-skill/main/README.md
  • apljacob/travel-agent（CC BY-NC）：7 阶段规划流程，要求每条具体结论先联网检索，带预订截止日追踪；Claude Code 插件形态。https://github.com/apljacob/travel-agent
  • 其他同类：skills-travel-planner（路书生成）、abalmeo/claude-skill-japan-recs（日本餐厅推荐）等。
  • 评估维度（结论用）：是否近期维护；是否含可执行 SKILL.md 而非纯提示词；是否日本/关西专项；是否依赖付费 API、第三方注册或海外数据源；许可证可否修改复用。
  • 结论：不安装任何第三方 Skill。 原因：
  1. 它们不自带 2025–2026 时效性事实库，仍靠联网检索，无法比本流程多提供“三源核验”；
  2. 安装会引入依赖、许可证和维护成本；
  3. 本任务用“官方源优先 + 多渠道交叉验证 + 状态标注”完成，质量更可控。
  • 从候选 Skill 中借鉴的两条原则已内化：每条具体事实现场检索，不凭记忆写票价/时刻；把“出发前/临行前需复查”单独列清单。

3.2 MCP / 插件判断

  • 结论：未新增任何 MCP 或付费工具。 理由：现有能力（网页搜索、网页打开、页内查找）覆盖官方网页、新闻、平台与社区页面；不涉及注册第三方收费平台；不需要浏览器自动化。
  • 小红书专辑（用户提供链接）实测：公开网页显示“该专辑还没收藏任何笔记”，正文区需登录/JS 渲染；移动端抓取失败；专辑 ID 与收藏者昵称全网无索引缓存。→ 处理方式：改用公开搜索 + 转载/镜像 + 其他平台交叉；无法打开的笔记不作为唯一来源。若用户后续提供单篇笔记分享链接或截图，可按第 7 节流程增补。

4. 信息来源分级与验证规则

4.1 来源分级

  • L1 官方一手：日本政府/机场/铁路/航司/酒店官网、中国出入境与驻日使领馆、香港机场与口岸官方、地方政府（如京都市交通局、大阪府）。
  • L2 平台/半官方：JNTO、观光局、大型预订平台（KKday/Trip.com）、专业机构（会计师事务所解读、媒体）。
  • L3 社区经验：小红书（2025 年后）、知乎、马蜂窝、豆瓣、B站、Reddit 等；仅作体验参考。

4.2 三源规则（核心）

  • 重要事实（签证、入境、海关、免税、票价、通票、离境税、防疫、现金额度等）：“≥3 条独立来源一致，且尽量含官方”才能标 ✅。
  • 只有 2 条来源、或官方+转载时：标 ⚠️，并注明差异或“以官方现行页为准”。
  • 只有 1 条来源或存在明显矛盾：标 ❗，并给出复核方法。
  • 经验类内容（排队实测、拍照点、避坑）：至少 2 条 2025 年后独立社区来源一致才写入；否则降级为 ❗ 或【建议】。
  • 每条来源标注检索日期；重要信息原则上不使用无日期旧文。

4.3 冲突与例外处理（v1 实例）

  • 日本烟草免税额度：海关官方英文页写纸烟 200 支，部分中文攻略写 400 支 → 以官方 200 支为准，正文注明分歧。
  • 回深圳免税额度：一般境外进境 5,000 元 vs 经香港/澳门进境居民 12,000 元（2024 年第 7 号公告）→ 两个口径并列说明，标注“以现场海关认定为准”。
  • 蛇口值机/截办时间：官方多页面版本不同（60/45/30/15 分钟）→ 全部列出并提醒以船票与码头当日公告为准。
  • 超长检索链接被截断时，来源清单中保留可辨认前缀（以“…”标示），并提示按标题检索原文。

5. 攻略正文标记体系

  • ✅ 三重一致：≥3 条独立来源一致（通常含官方/准官方）。
  • ⚠️ 基本可用：2 条来源，或官方+转载；来源间有出入时已注明差异。
  • ❗ 待核实：未取得 3 条来源，或存在矛盾/未三源验证；出行前必须自行确认。
  • ⏰ 时效性：班次、票价、天气、政策过渡类；出发前 1–7 天复查。
  • 【建议】：通用旅行建议，不构成事实承诺，不要求三源。
  • 引用：正文用〔S#〕指向文末来源清单；来源清单格式为“S# ｜ 类型 ｜ 名称 ｜ URL ｜ 检索日期 ｜ 备注”。

6. 检索方法（v1 实操模板）

6.1 按主题的首选官方入口

  • 日本签证/eVISA：日本驻华大使馆、外务省（MOFA）官网
  • 入境/海关/VJW：数字厅 Visit Japan Web、日本海关（customs.go.jp）、关西机场官网
  • 铁路/通票：JR 西日本、jr-group 票价页、京都市交通局、Osaka Metro、阪急/京阪官网
  • 机场巴士：关西机场交通（KATE）
  • 港深接驳：蛇口邮轮母港（cmskchp.com）、香港民航处 APDT、各航司官网
  • 免税：日本海关 FAQ、国税厅/观光厅相关页、Japan-Guide 等更新报道
  • 中国入境：中国政府网/财政部/海关总署公告、驻外使领馆提示
  • 天气/灾害：日本气象厅（JMA）、关西气象台；台风季用 JMA 台风信息
  • 景点：各寺社/设施官网；USJ 官方购票页；嵯峨野观光铁道官网

6.2 检索词模板

  • 日文官方优先：如「京都市交通局 地下鉄・バス一日券 公式」「特急はるか 料金 公式」
  • 中文核验：如「2026 日本入境 VJW」「2026-11 免税新制度」
  • 社区时效：限定 2025/2026，如「2025 国庆 关西 游记」「小红书 大阪 京都 2026」
  • 英文交叉：如 "Kansai Area Pass discontinued 2026"、"tax-free refund November 2026"

6.3 社区/小红书内容的处理

  • 小红书网页普遍需要登录；优先采用：公开搜索结果摘要、可访问的转载页、用户提供的单篇分享链接。
  • 单篇分享链接若可读：抓取正文 → 抽取可核验事实 → 按三源规则与其他来源交叉 → 在攻略中补条目并在来源清单新增 S#。
  • 平台笔记数据（点赞/收藏/时间）不作为事实依据；只作为“热度参考”，不写入攻略。
  • 同一经验至少 2 篇独立内容一致才采用；署名不清、无日期的旧内容不采用。

7. 更新流程

7.1 触发更新的场景

  • 用户提供：航班号/日期、酒店区域、实际行程、小红书单篇链接或截图。
  • 客观变化：政策（入境/免税/海关）、票价与班次（Haruka/巴士/船班）、天气与台风、景点临时闭馆、通票发售终止。
  • 出发临近：VJW 流程、京都巴士“市民优先价格”是否落地、USJ 当日票价与人流。

7.2 操作步骤

  1. 定位受影响条目（用来源 S# 反查）。
  2. 按 L1→L2→L3 顺序重新检索，尽量凑齐 3 条来源；无法凑齐就降级标注。
  3. 更新攻略正文（含状态标记），在来源清单追加新 S#（旧 S# 保留，注明“已复核/已过期”）。
  4. 同步更新制作指南的“更新记录”和“已知缺口”。
  5. 升版本号 v1 → v2（文件名与文档内版本行同步）。
  6. 重新生成 HTML 检索版：

```text

node tools/build-site.js Osaka-Kyoto-NationalDay-Travel-Guide-v2.md Osaka-Kyoto-NationalDay-Travel-Guide-v2.html --inline-images --home index.html

node tools/build-site.js Osaka-Kyoto-Transit-Guide-v2.md Osaka-Kyoto-Transit-Guide-v2.html --inline-images --home index.html

```

7.3 配套脚本

  • tools/build-site.js：把 Markdown 转成带左侧目录、目录筛选、表格与图片（可内嵌为单文件）的响应式 HTML（用法见 7.2）。
  • tools/publish.ps1：一条命令完成「重建网页 → 校验 → 同步到仓库 → 提交推送」，用于本地更新后自动上传 GitHub。
  • split-docs.js：v1 拆分用的一次性脚本（合并版 → 攻略版），后续更新无需再运行。

8. v1 已知缺口与下一步

  • 未取得用户航班号/日期与酒店区域：蛇口参与航司与行李直挂名单、船班衔接、Haruka/巴士末班、USJ 当日票价等无法精确到“天”。
  • 小红书专辑内容未获取（登录墙/显示为空），等待用户提供单篇链接或截图。
  • 部分平台/媒体链接较长且被检索结果截断，仅保留前缀。
  • 若离境日跨过 2026-11-01：购物部分需按“先付含税、出境退税”新制改写。
  • 京都市巴士拟议中的“市民优先价格”（市外游客 350–400 日元）目标 2027 年度实施，2027 年后出行需重算巴士票券性价比。
  • 10 月台风与天气属动态信息，攻略只给气候常识，出发前 1 周与 48 小时需按 JMA 复核。
